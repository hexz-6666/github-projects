### 3. 项目事实基线，不是本次新需求

- 当前是一个单一项目，不是 Kimi、DeepSeek 两个独立子项目。Kimi3 交付的是架构、数据字典、API 契约、数据来源和隐私约束；`docs/premise-review.md` 是 DeepSeek 实施前审查。
- 技术栈是 Vue 3 + Vite、Spring Boot 2.7、FastAPI、MySQL 8.0；前端只访问 Java，Java 访问 MySQL 和 FastAPI，Python 不直接访问 MySQL。
- 已有登录、角色、CSRF、订单、异常队列、详情复核、数据质量、模型评估、健康检查和审计。当前前端没有图表库、工单配置模块或前端日志中心。
- v1/v2 的路径、字段、分页、错误码、标签语义、数据来源和隐私边界已经冻结。新功能优先使用 v3 增量契约，不静默改写 v1/v2。
- Olist 没有直接欺诈标签；IEEE-CIS 的 `isFraud` 只属于 IEEE-CIS 独立评测域。两者不得拼接、互相补标或在同一图表中暗示可比较。
- 规则分不是欺诈概率，告警不是欺诈事实，人工复核不是客观真值。UI 统一使用“风险分、风险告警、复核结论”等准确文案。
- 本机 MySQL 尚未以可用最小权限账号完成真实验证，真实 Olist/IEEE 数据也未验收。没有新增凭据时只能如实保留该限制。
- `runtime/*.log` 是本机运行产物并被 Git 忽略，不是可直接暴露给浏览器的安全日志接口。
- 当前导入和模型训练并不是完整的异步任务平台。未明确前，不得把同步调用包装成已经具备调度、重试、取消和恢复能力的“任务系统”。

### 5. 本次用户新需求

#### 5.1 登录界面和记住账号/密码

目标：按照图二的简约风格重做现有登录页，保持项目身份和安全边界。

实现要求：

- 桌面端使用左右构图：左侧为订单风险或数据分析主题视觉，右侧为克制的登录区域；移动端优先表单，可隐藏非必要大图，390 x 844 下不得横向溢出。
- 保留项目名称、非生产演示提示、错误态、加载态、键盘操作和可读焦点。演示账号快捷入口可以保留，但应弱化，不得让真实部署误用默认密码。
- 账号输入使用稳定的 `name` 和 `autocomplete="username"`；密码输入使用 `autocomplete="current-password"`，允许浏览器原生密码管理器保存和自动填充。
- “记住账号”仅在用户主动勾选时把用户名存入 localStorage；取消勾选或退出时按产品决定清除，必须写测试。
- 绝不把密码写入 localStorage、sessionStorage、IndexedDB、URL、普通 Cookie、日志或前端源码。不要用可逆加密后再存浏览器来伪装安全。
- 若需要“保持登录”，使用服务端持久会话和不透明 Session Cookie：`HttpOnly`、`SameSite=Lax`，HTTPS 下 `Secure`，明确 7 天或用户确认的期限，登录时轮换会话，退出时服务端失效。UI 文案建议用“保持登录”，不要误导为应用自行保存明文密码。
- 现有 Session、CSRF、401/403 语义必须保持；增加持久会话属于契约和安全变更，先提案再实现。

验收：

- 勾选“记住账号”后刷新仍显示账号，取消后不再保存。
- 浏览器可通过标准密码管理器保存/填充密码，但 DevTools 的 Web Storage 中找不到密码。
- 登录失败不建立会话；登录成功后会话 ID 轮换；退出后旧会话不可继续调用业务 API。
- 桌面和 390 x 844 移动视口无重叠、截断或横向滚动。

#### 5.3 工单配置新模块

首选业务定义：将现有风险告警转换为“复核工单”，工单用于分派、SLA 和处理进度，不把它称为欺诈事实。通用工单平台会明显扩大范围，除非用户明确选择，否则不做。

若用户选择“仅配置模板”，最小闭环包括：配置列表、搜索/筛选、新建、编辑、校验、预览匹配量、发布、停用、版本记录和审计；不得声称已自动生成或执行工单。

若用户选择“完整但最小流程”，在上述基础上增加告警转工单、幂等去重、分派、状态流转、SLA 到期时间、处理记录及与原告警/复核记录的可追踪关系。不要为本科规模项目引入通用 BPMN 引擎。

推荐配置字段：

- `code`、`name`、`description`、`enabled`、`priority`。
- 适用来源、风险级别、告警状态等触发条件。阈值字段必须标明是风险分阈值，不得写“欺诈概率”。
- 分派角色/策略、SLA 分钟数、是否需要复核。
- `version`、`expectedVersion`、发布状态、创建/修改人和 UTC 时间。
- 条件 JSON 必须使用结构化 JSON 解析和白名单校验，不得手工拼字符串或允许任意表达式执行。

推荐增量 API（最终命名先写入 v3 契约并确认）：

- `GET /api/v3/work-order-configs`：分页、关键字、启用状态。
- `GET /api/v3/work-order-configs/{id}`。
- `POST /api/v3/work-order-configs`。
- `PUT /api/v3/work-order-configs/{id}`：必须带 `expectedVersion`，冲突返回 409。
- `POST /api/v3/work-order-configs/{id}/publish`。
- `POST /api/v3/work-order-configs/{id}/disable`：优先停用，不物理删除有历史引用的配置。
- `POST /api/v3/work-order-configs/preview`：只返回匹配数量和分组统计，不返回敏感原始行。
- 若做完整流程，再增加 `/api/v3/work-orders` 查询、详情、分派和状态流转接口。

权限：

- `ADMIN` 可新建、编辑、发布和停用配置。
- `REVIEWER` 可查看配置和处理已分派工单。
- `ANALYST` 默认只读；是否可处理工单由用户确认。
- 所有配置变更和工单状态变更写追加式审计，操作者从服务端会话取得，不能相信请求体中的用户 ID。

数据建议：

- 用新迁移新增配置、配置版本和可选工单实例表，不修改历史迁移。
- 工单实例对 `alert_id` 做明确的幂等约束；配置发布使用版本快照，后续修改不能篡改已生成工单的解释依据。
- stub 与 MySQL 实现保持字段和错误语义一致；只验证 stub 时必须标记 MySQL 未验证。

#### 5.4 前端日志小窗口与统一日志记录

目标：管理员在前端看到与工单配置、导入、模型训练和工单执行相关的脱敏错误/状态日志，并可用 `requestId`、`taskId` 追踪前后端链路。它不是任意读取服务器文件的终端。

安全架构：

- 不允许前端直接读取 `runtime/*.log`，不提供任意文件路径参数，不返回原始堆栈、SQL、主机、内部 URL、请求正文、Cookie、密码、邮箱、卡/地址标识、模型特征值或 IEEE 行级数据。
- 使用结构化运行事件，而不是把整行文本当接口。建议字段：`eventId`、`timestamp`、`source`（FRONTEND/BACKEND/MODEL/TASK）、`level`、`taskType`、`taskId`、`stage`、`code`、`summary`、`requestId`、`actorId`、`durationMs`、经过白名单校验的 `safeDetail`。
- 前端错误只上报允许的错误名、截断后的安全消息、前端路由、`requestId` 和构建版本；接口必须认证、限流、限制长度并在服务端再次脱敏。
- Java 在统一异常处理、导入、训练、配置发布和工单执行边界记录事件；模型服务的细粒度阶段如需展示，应通过新的内部结构化契约返回或上报，不抓取 Python 原始控制台。
- 日志保存采用追加式事件和明确保留策略，例如演示环境 7 天或最多 10,000 条，并可配置。日志 UI 不提供删除服务器审计记录的按钮。

推荐 API：

- `GET /api/v3/ops/logs?source=&level=&taskType=&taskId=&requestId=&from=&to=&cursor=&limit=`，仅 `ADMIN`，游标分页，`limit` 有上限。
- `POST /api/v3/ops/client-errors`，仅已登录客户端，上报固定结构，服务端限流/截断/脱敏。
- 第一版用 3 至 5 秒轮询即可；确有实时性需求再增加 SSE。不要为小项目先引入 WebSocket 或外部日志平台。

前端交互：

- 右下角日志按钮打开可扩展小窗口/底部抽屉，支持来源、级别、任务类型、关键字/关联 ID 过滤，暂停自动刷新、清屏仅清当前视图、复制 `requestId`。
- 窗口必须有未读错误计数、加载/空/断线/无权限状态；默认只显示 WARN/ERROR，避免 INFO 淹没错误。
- 桌面不遮挡关键操作，移动端改为全屏对话框；键盘可关闭，焦点可恢复。
- 工单配置保存或发布失败时，界面错误提示包含安全错误码和 `requestId`，可一键在日志窗口中过滤该请求。

#### 5.5 图形化看板

目标：只使用真实 API 或明确标注的合成演示数据，按项目现有语义实现折线图、饼图、柱状图和雷达图。不能为了凑图表随机造数。

推荐使用 Apache ECharts 的按需引入方式；新增前先说明固定版本、Apache-2.0 许可证、包体影响，并实现 `ResizeObserver`、组件卸载 dispose、空态和文本/表格替代。

建议映射：

- 折线图：选定时间范围内的订单量、风险告警量、已完成复核工单量趋势。后端按天/周聚合，日期缺口补 0 的逻辑放在明确的一层并测试。

- 雷达图：比较两个或以上 IEEE-CIS 模型版本的 `PR-AUC`、`Recall@FPR1%`、`Recall@FPR5%`、`Precision@100` 和 `1 - Brier`。所有轴统一到 0 至 1，明确归一化公式；缺失指标不当 0，只有一个模型时显示选择提示而不是伪造对比。

可新增一个 v3 聚合端点，例如 `GET /api/v3/dashboard/overview?from=&to=&bucket=day`，返回摘要、趋势、分布和批次质量统计；模型雷达图可复用 `/api/v2/evaluations`，但须在前端保留“仅 IEEE-CIS 独立评测、合成夹具不代表真实效果”的说明。

所有图表必须具备：

- 标题、时间范围、单位、数据来源、图例、tooltip、加载态、空态、错误态。
- 对应的可访问文本摘要或数据表。
- API 返回值与图中数值的一致性测试。
- 1440px 桌面和 390 x 844 移动端截图检查，图表非空白、图例不遮挡、文字不截断、无横向溢出。
- Olist 订单统计与 IEEE-CIS 模型评测分区展示，禁止合并成一个“欺诈效果”看板。

### 7. 测试与验收最低要求

#### 后端

- 工单配置 CRUD、字段校验、发布/停用、预览、角色权限、CSRF、审计和 409 乐观锁冲突。
- 完整流程若启用：同一告警重复触发不重复建单，非法状态流转被拒绝，SLA 使用 UTC，操作者不可伪造。
- 日志查询的 ADMIN 权限、游标分页、过滤、长度上限、限流和敏感字段脱敏。
- 聚合接口的时间边界、时区、空数据、缺失日期、分组总数与明细总数一致。
- stub 与 MySQL 契约测试分开；无数据库账号时不宣称 MySQL 通过。
